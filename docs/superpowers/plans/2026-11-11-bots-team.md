# Bot Page Team Features Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spec B — Chief starts a group's work, a "Needs you" strip, a list that says what is going on, scheduled runs that keep quiet or say they failed, pause/duplicate/export/import, ask aside, a first-run card, and usage that compares and drills down.

**Architecture:** Everything rides on what spec A built: a group round starts from `bot_groups.pending` (new reasons `chief` and `task` join `time`/`running` as resumable) and is driven by `continueGroup`; a turn's `origin` gates what it may do. New state is a handful of columns (schema 46); the list reads it in the one team read plus one attention read. The page stays one module (`public/js/bots.js`) with the new pieces in small modules beside it.

**Tech Stack:** Node 22 ESM, Express, Postgres (pg; PGlite in tests), vanilla JS, the repo's `check()` harness, Playwright UI tests.

**Spec:** `docs/superpowers/specs/2026-11-10-bots-team-features-design.md`.

## Global Constraints

- Schema version **46**. `scheduled_tasks.last_status` already exists and carries the failure ("failed: …"), so no `last_error` column.
- Every route scoped to the account; another account's id answers 404.
- Every new string in vi and en; `test/i18n.test.mjs` and `test/server-i18n.test.mjs` pass.
- No model call the person did not cause: the first-run card makes none; ask aside is one call the person asked for; post_to_group runs only from a turn the person started.
- The hand-off ceiling (6) and segment ceiling (8) apply to rounds Chief or a task starts, exactly as to the person's.
- `post_to_group`, `no_update`, `run_failed` cost tokens on every step they are offered: `post_to_group` only to Chief; `no_update`/`run_failed` only in unattended runs. `test/model-surface.test.mjs` budgets re-measured, not guessed.
- Imports never carry secrets: every memory entry and instruction goes through `redactSecrets`; task schedules come in paused.
- Browser suites from this checkout only; never `test:ui` beside the gate.
- CLAUDE.md §5; `npm run gate` green before merging.

- `claimDueTask` skips tasks of a paused bot.
- `createTask` takes `botGroupId`, `missed`; `listTasks(userId, { botId, groupId })`; `updateTask` allow-list + `missed`, `enabled`.
- `copyBotMemory(userId, fromBotId, toBotId) → n`.
- `recordUsage` takes `reasoningTokens`, `origin`; `usage.record` passes `usage.reasoning` and `origin`.
- `botUsageTotal(userId, { from, to }) → { tokens, cost }`; `botUsageDetail(userId, botId, { from, to }) → { kinds: { input, cached, output, reasoning }, models: [{ model, tokens, cost }], groups: [{ group_id, tokens }], origins: [{ origin, tokens }], roles: [{ role, tokens, cost }] }`.

### Task 2: Scheduled runs that keep quiet or fail (B.4)

**Files:** `server/tools/runControl.js` (new), `server/agent.js`, `server/scheduler.js`, `server/tools/definitions.js` (schedule_task: `missed`, description), `server/bots/prompt.js`; Test `test/bots-team.test.mjs`.

**Produces:**
- `RUN_CONTROL_TOOLS` — `no_update()` and `run_failed({ reason ≤ 300 })`, offered only when `unattended`; executed in the loop (no catalogue entry): emit `run_outcome { kind: 'quiet' | 'failed', reason }`, stamp the run's final assistant message `quiet: true` (quiet), and end the turn.
- `runTask`: reads `run_outcome` → status `ok: nothing new` (quiet) or `failed: <reason>`; `missed === 'skip'` and more than `MISSED_GRACE_MS = 30 min` late → no run, status `skipped: missed`, schedule moves on; a task with `bot_group_id` posts its prompt as the person's line (`origin: 'task'`) and runs the round through `startPendingRound` + `continueGroup` (Task 3), status from the round's end.
- `botPreviews`/unread ignore `quiet` lines; the page folds a quiet answer under its run marker.
- Prompt text (bot prompt + schedule_task description): each run starts from the newest messages only; say what to check, how, what to report, when to report nothing (`no_update`).

- [ ] Steps: failing tests (quiet run leaves no unread and status `ok: nothing new`; run_failed status; skip vs once; group task runs a round) → implement → `node test/bots-team.test.mjs && node test/scheduler.test.mjs` → commit `feat(tasks): runs that have nothing to say keep quiet; failed runs say why; missed runs skip or run once; group tasks`.

### Task 3: Chief starts a group's work, paused members, member states (B.1, B.3 strip, B.5 pause in rounds)

**Files:** `server/bots/rounds.js`, `server/bots/continue.js`, `server/bots/tools.js`, `server/routes/bots.js`; Test `test/bots-team.test.mjs`, `test/bots-core.test.mjs`.

**Produces:**
- `RESUMABLE = new Set(['time', 'running', 'chief', 'task'])` exported from rounds.js, used by rounds, continue, the heartbeat query and the team route.
- `startPendingRound({ userId, groupId, line, reason, notify }) → { started: boolean, why? }` — refuses when a round is running or waiting; posts `line` (Chief's: `{ role: 'assistant', bot: chiefId, text, via: 'chief' }`; a task's: `{ role: 'user', text, origin: 'task' }`); queues the named members or the admin with `person: 'chief' | 'task'` (origin `handoff` / `task`); saves `pending { reason, notify }`.
- `post_to_group({ group, message })`: Chief only, person-started only (TEAM_CHANGING); `startPendingRound` then `chainNext`; result "Started in {group}…".
- Round end: `pending.notify.chatId` → one assistant line in Chief's chat, in the person's language: "{group} xong — xem nhóm" / "{group} is done — see the group".
- `state.called = [{ bot, how: 'called' | 'working' | 'answered' | 'passed' | 'failed', tool }]` kept per person message; the live route returns it.
- A paused member called in a round: notice `paused` ("X đang tạm dừng"), counted as passed.

- [ ] Steps: failing tests (post_to_group refused for a member and for a handoff/task origin; runs a round; Chief's chat gets the done line; paused member skipped; `called` states) → implement → `node test/bots-team.test.mjs && node test/bots-core.test.mjs && node test/bots.test.mjs` → commit `feat(bots): Chief starts a group's work; paused bots sit rounds out; who is called and how each went`.
