# Key Pools Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spec A — up to five keys per deployment service, added by the owner in Settings → Administration → Free allowances; each service's capacity is the sum of its keys; a spent, refused or rate-limited key hands over to the next; one owner-chosen paid key per service takes charged calls once every free key is full.

**Architecture:** A new `server/keyPool.js` owns the keys (environment key = key 1, the rest in table `service_keys`, sealed with crypto v2), per-key counting buckets, choosing a key (largest share left), and classifying a provider's refusal into a key state. `freeTier.js` asks it for a service's capacity and counts per key. Every place that read `process.env.<X>_API_KEY` for a pooled service goes through `withKey(service, need, run, { paid })`. The admin route and page show and manage it.

**Tech Stack:** Node 22 ESM, Express, Postgres (pg; PGlite in tests), vanilla JS front end, the repo's `check()` test harness, Playwright for browser suites.

**Spec:** `docs/superpowers/specs/2026-11-12-key-pools-design.md`. Research: `docs/research/2026-11-12-key-usage-apis.md`.

## Global Constraints

- Schema **52**: table `service_keys`; the section goes in `schema.sql` **above** the Schema 49 RLS `DO $$` block, which stays last. `SCHEMA_VERSION = 52` plus its comment line in `server/store/pg.js`.
- Pooled services, exactly (owner, 2026-11-12: "only Exa, Tavily, Firecrawl have 4–5 keys, maybe more; the rest one key"): `exa`, `tavily`, `firecrawl` with `maxKeys: 10`; `brave`, `e2b` with `maxKeys: 1` (in the pool only for the paid-key rule and key states). `google`, `coingecko`, `fred`, `resend` are not pooled and their code is not touched. Not pooled with a reason shown: `stackexchange` (quota per server address), `thesportsdb` (one public free key).
- At most **`maxKeys` keys per service**, the environment key included. The environment key is `id: 'env'`, never stored, never removable in the page, and keeps today's bucket names (`free:<service>:<period>`) so this month's counts carry over. Stored keys count in `free:<service>@<keyId>:<period>`.
- Default per-key free ceilings: exa 9,500 mills/month; tavily 950 credits/month; brave 950 requests/month; firecrawl 95% of live `planCredits` (fallback 950)/its billing period; e2b `e2bMonthCap()` on its one key. Each env-overridable as today (the env value is the per-key default).
- Choose: healthy key with the largest `left / ceiling`; ties → lowest index. Paid key only when no free key has room AND (`paid: true` OR `FREE_TIER_ONLY=false`), and only under its `capMonthly`.
- Refusal classes: invalid (401, 403, Exa `INVALID_API_KEY`, Brave 422 `SUBSCRIPTION_TOKEN_INVALID`) · exhausted (402, Tavily 432/433, Exa `NO_MORE_CREDITS`/`*_BUDGET_EXCEEDED`) · cooling (429; `Retry-After` clamped to 30 s–10 min) · transient: a 5xx → the next key once, state unchanged; a **timeout → no other key** (owner, 2026-11-12: a slow provider is slow for every key; the search chain is already the retry) — the call stands aside or fails as before, state unchanged. A Firecrawl 403 that does not name the token/key is a refusal of the request (a blocked site), not of the key — no state change.
- Add/remove/check/paid routes are **owner only**; viewing needs `free_tier`. Keys never leave the server — responses, logs, audit rows and errors carry `hint` (last 4) only. Validity checks call fixed URLs only.
- Live usage only on the admin page's request (cached: Tavily 5 min, Firecrawl 2 min) and Firecrawl's existing ten-minute refresh; never on a person's request path.
- Every new string in `public/js/locales/{en,vi}.js` and, for server messages, `server/i18n/vi.js`. CLAUDE.md §5. `npm run gate` green, then every browser suite (`npm run test:ui`) — run them one after the other, never side by side.
- Working tree is CRLF: edit with the Edit tool or a CRLF-aware node helper; never leave a lone CR. Stage files by path (unrelated untracked folders sit in the tree).
- Release **1.29.0** (Task 6).

**Interfaces:**
- Produces (store, all `async`):

  - `addServiceKey({ id, service, sealed, fingerprint, hint, label, ceiling, addedBy }) → row` — throws `Object.assign(new Error('That key is already in this service.'), { code: 'duplicate' })` on the unique violation.

- Produces: `serviceKeyContext(service, id) → ['service-key', service, id]`.

DDL:

```sql
-- ── Schema 52 ────────────────────────────────────────────────────────────────
-- Several keys per deployment service (owner, 2026-11-12, server/keyPool.js): the
-- environment's key is key 1 and is never stored; the owner adds up to four more in
-- Settings → Administration → Free allowances. `sealed` is crypto v2 bound to
-- ['service-key', service, id]; `fingerprint` is sha256(service:key) so the same key
-- twice is refused; `hint` its last four characters — all the page ever shows.
CREATE TABLE IF NOT EXISTS service_keys (
  id          TEXT PRIMARY KEY,
  service     TEXT NOT NULL,
  sealed      TEXT NOT NULL,
  fingerprint TEXT NOT NULL,
  hint        TEXT NOT NULL,
  label       TEXT,
  ceiling     DOUBLE PRECISION,
  state       TEXT NOT NULL DEFAULT 'ok',
  state_at    TIMESTAMPTZ,
  retry_at    TIMESTAMPTZ,
  live        JSONB,
  last_error  TEXT,
  added_by    TEXT REFERENCES users(id) ON DELETE SET NULL,
  added_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  UNIQUE (service, fingerprint)
);
CREATE INDEX IF NOT EXISTS service_keys_service_idx ON service_keys (service, added_at);
```

**Interfaces:**
- Consumes: Task 1 store methods; `encryptSecret`/`openSecret`/`sha256` (crypto.js); `serviceKeyContext`.
- Produces (`server/keyPool.js`):
  - `POOLED: Readonly<Record<string, { env: string[], unit: 'mills'|'credits'|'requests', label: string }>>` and `NOT_POOLED: Readonly<Record<string, string>>` (service → reason message id).
  - `async keysFor(service, { fresh = false } = {}) → Array<{ id: string, fromEnv: boolean, key: string, hint: string, label: string|null, ceiling: number|null, state: 'ok'|'invalid'|'exhausted'|'cooling', retryAt: number|null, live: any }>` — env key first (when set), then stored keys; cached per instance 30 s; the cache is dropped when the setting `service_keys_version` differs (read at most every 30 s).
  - `poolHas(service) → boolean` — synchronous, from the last snapshot (env key counts without one).
  - `async warmPools() → void` — loads every pooled service's snapshot once per 30 s.
  - `keyBucket(service, keyId, now = new Date(), { paid = false } = {}) → { bucket: string, ends: Date }` — `free:<service>:<period>` for `'env'`, `free:<service>@<id>:<period>` otherwise; `paid:<service>@<keyId>:<month>` when `paid`.
  - `async ceilingOf(service, key, now) → number` — override → live×0.95 → default.
  - `async leftOf(service, key, now) → number` — `max(0, ceiling − used)`, lowered to the provider's live remaining when that is lower.
  - `async pickKey(service, need, { paid = false } = {}) → { key, paid: boolean } | null`.
  - `classify(service, { status, code, body }) → 'invalid'|'exhausted'|'cooling'|'transient'|null`.
  - `async markKey(service, key, state, { retryAfterMs = 0, error = '' } = {}) → void` — env key's state lives in memory only (per instance) and in the setting `service_env_state`.
  - `async withKey(service, need, run, { paid = false } = {}) → any` — `run(key: string, meta: { id, paid }) ` may throw an error carrying `status`, `code`, `body`; tries the next key per class; when every key is out throws `Object.assign(new Error(`${service}: no key with room`), { skip: true })`.
  - `async paidKeyOf(service) → { keyId: string, capMonthly: number|null } | null`; `async setPaidKey(service, keyId|null, capMonthly|null) → void`.
  - `async countPaid(service, keyId, amount, now)`.
  - `async liveUsage(service, key, { fresh = false } = {}) → { plan, used, limit, resets, at } | null` (Tavily `GET https://api.tavily.com/usage`, Firecrawl `GET https://api.firecrawl.dev/v2/team/credit-usage`; others null).
  - `async checkKey(service, key) → { ok: true, plan?: string } | { ok: false, reason: 'refused'|'unreachable'|'template' }` — the fixed validity calls from the spec table.
  - `async poolReport(now) → Array<{ service, pooled: boolean, note?: string, keys: Array<{ id, fromEnv, hint, label, plan, used, limit, resets, source: 'provider'|'counted', state, retryAt, paid: boolean }>, paid: { keyId, capMonthly, spent } | null }>`.
- Changes `server/freeTier.js`: `allowance(service)` for a pooled service = `{ left: Σ leftOf, limit: Σ ceilingOf }`; `take/spend/refund/exhaust(service, amount, now, { keyId = 'env', paid = false } = {})` write the key's bucket (paid → also `countPaid`); the Firecrawl share services (`firecrawl_search` 0.6, `firecrawl_scrape` 0.35, `firecrawl_more` 0.05, `firecrawl_index` daily 950 per key) take their limits from Σ firecrawl capacity; `freeTierReport` adds `pool: await poolReport(now)`.
